# 使用与维护

## 首次设置

安装后在 LSPosed 启用云漾，作用域仅选择系统界面。重启 SystemUI 或设备加载当前 Hook。打开云漾按 KernelSU 提示授权，然后开启通知访问、通知和 Live Update；缺失权限的入口显示在设置中，授权后隐藏。

“应用”页按名称或包名搜索，勾选并点击“保存选择”；搜索过滤不会清除隐藏项的勾选。“设置”页调整时长、右侧滚动和手动下岛按钮。新安装默认停留 15 秒，已有安装保留自己的设置。

Root 启用还会通过 appops 允许本应用的使用情况访问，用于识别直接进入来源应用；没有 Root 时可自行在系统设置开启。监听读到通知后，并不会自动打开配置界面或来源应用，只有用户点击相应通知操作才发送原始点击 Intent。

## 首次授权与撤销

`root_setup_attempted` 是云漾保存的“已经做过初始化尝试”，KernelSU 授权记录则由 Root 管理器保存。首次拒绝、失败、进程中断后，云漾不会在每次进入时反复弹请求。

设置页的“Root 保活”卡片显示已保存的授权状态。“启用 / 刷新 Root 保活”可在首次失败后手动重试或重新部署看护；“停止 Root 保活”用于清理看护。操作期间两个按钮禁用，完成后恢复。首次自动授权逻辑保留，日常进入界面不重新检测或弹出授权。开发者也可通过下面的 Root 私有接口显式重试：

```bash
adb shell su -c 'content call --user 0 --uri content://com.bajiao.notificationisland.runtime --method root_enable'
```

撤回 su 授权**不等于已经结束先前启动的 Root shell**。需要彻底移除看护时，应先在授权仍可用的情况下点击“停止 Root 保活”，随后再撤销 Root 权限或卸载。等效的开发接口为：

```bash
adb shell su -c 'content call --user 0 --uri content://com.bajiao.notificationisland.runtime --method root_disable'
```

停止操作会清理本应用看护和开机入口、移除 Doze 白名单并恢复监测进程回收分值。仅卸载 APK 时，Android 不保证清除 `/data/adb` 里的脚本；如果 APK 已卸载，需由机主在 Root 文件管理器中核对并移除 `notification-island.sh` 及 `/data/adb/notification_island/`。不要清理其他应用目录。

## 行为说明

- 下岛隐藏云漾的中转项，原消息通知保留。同 key 更新仍隐藏，原通知移除后才解除抑制。
- “打开”先隐藏当前中转，再发送原通知 Intent；原 Intent 失效时给出提示。
- 直接打开来源应用的识别受 UsageStats 和 3 秒同步周期影响；不是应用一到前台就保证瞬间下岛。
- 没有候选时停止呈现服务；通知监听继续由系统绑定，不显示长期待命通知。
- 移除最近任务不主动终止 monitor，但显式强停、厂商管理器或其他模块可能影响恢复。
- 无 Root 仍可尝试系统通知监听和前台服务路径，但 ColorOS 冻结/启动限制下可靠性可能降低。

## 故障信息

测试通知能上岛只说明云漾自身可发布提升通知，不证明来源应用通知已经通过监听和过滤。检查勾选是否保存、通知是否为摘要、相同 key 是否已被下岛或到期抑制。先移除来源旧通知，再发布新通知更容易排除抑制影响。

有岛但名称、图标或滚动不对时，检查 SystemUI 作用域和是否加载当前 Hook。正文超出五字宽还需开启滚动设置，展开面板不应滚动。

提交 Issue 时写明设备型号、完整 ROM / Android 版本、KernelSU 与 LSPosed 版本、重现步骤和是否在关闭界面后发生。请先脱敏，不上传聊天正文、通知 key、私人截图、系统数据库或完整设备日志。

## 流体云推送总开关

首页“快捷操作”中的“流体云推送”默认开启。关闭后立即撤掉当前岛并停止展示服务，消息监测与 Root 看护继续运行，测试上岛按钮暂时禁用；开关状态保存在本机。重新开启时会恢复仍有效、尚未抑制且未过期的来源通知，已手动下岛或已过期的通知不会因此解除抑制。
